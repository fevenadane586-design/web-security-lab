Web Security Lab

Break it, then fix it. Four common web vulnerabilities, each with a vulnerable and a secure version.

1. Cross-Site Scripting (XSS)

OWASP Top 10 (2021): A03 Injection

A comment box shows what users write. If the page inserts the comment as HTML, an attacker can hide a script inside it, and that script runs in every visitor's browser.

Vulnerable version

Attacker's script ran in your page!
box.innerHTML = comment;

Secure version

box.textContent = comment;

The fix: never insert user input as HTML. Use textContent so the browser treats it as plain text. Also escape output on the server and add a Content Security Policy.

2. SQL Injection (simulated)

OWASP Top 10 (2021): A03 Injection

A login form builds a database query from what you type. If the input is pasted straight into the query, an attacker can change the query itself. Valid accounts: admin and feven.

Vulnerable version

Query sent to the database:

query = "... username = '" + user + "'"

Secure version

Query and parameters sent separately:

db.query("... username = ?", [user])

The fix: use parameterized queries (prepared statements). The database receives the query and the data separately, so input can never change the query's structure. Also apply least privilege to the database account.

This is a simplified simulation that recognizes common injection patterns. It does not use a real database.

3. Password Storage

OWASP Top 10 (2021): A02 Cryptographic Failures

Imagine an attacker steals a website's database. What they can do depends on how passwords were stored. Enter a password to see three storage methods, then let the attacker try a small wordlist.

Plain text

Unsalted SHA-256

Salted PBKDF2

The fix: store passwords with a slow, salted algorithm (PBKDF2, bcrypt, scrypt or Argon2). The salt stops precomputed tables, and the slowness makes every guess expensive. Notice that even the secure method cannot save a very weak password, so strong passwords still matter.

4. Brute Force Login

OWASP Top 10 (2021): A07 Identification and Authentication Failures

An attacker tries a list of 12 common passwords against one account. The target's real password is on the list. Compare a login with no protection against one that locks the account after 5 failed attempts.

No protection

Lockout after 5 failures

The fix: combine rate limiting, temporary lockouts, multi-factor authentication and breach-password checks. Note that hard lockouts can be abused to lock real users out, so many systems use increasing delays instead.

Educational project. Every attack here runs only inside this page, against fake data. Never test these techniques on systems you do not own or have written permission to test.
